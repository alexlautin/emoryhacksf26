Local monitor for coding agents

See what your
coding agent
actually runs.

An install can finish in the agent's window while a package script reads a key and tries to send it off. Lookout follows that chain on your machine, from the agent through the shell and npm down to the script, and writes down what it finds.

You asked the agent to set up the project. Its window shows the install.

  2. color-helpers install script Dangerous

    The connection, from lsof. Port 4199 is the demo's stand-in server. It counts bytes and drops them.

Auto-protect defaults to pausing on Dangerous. The demo sleeps between steps so the half-second poll can see the script.

How it works

Agent, shell, npm, install script, curl.

Lookout polls the process list every 500 ms and walks parent pointers until it hits an agent, or doesn't. A process that starts and exits inside that gap can be missed. The five steps below are the shape it is built to follow.

  1. 01

    claude

    The agent

    A process named claude, codex, gemini, cursor-agent, copilot, opencode, or amp opens a session. The scripted demo counts too. macOS uses ps. Windows uses one long-running PowerShell query of Win32_Process.

  2. 02

    zsh -lc

    The shell it started

    Agents wrap the real command. Lookout pulls it back out of zsh -lc, bash -c, cmd /c, PowerShell -Command, and Claude Code's eval form.

  3. 03

    npm install

    What the window shows

    Installing packages is low risk by itself. The same rule covers pnpm, yarn, bun, pip, and uv. The interesting part is usually the child, not this line.

  4. 04

    install.js

    Outside the agent's window

    In the demo, install.js starts a shell under npm. When that shell does something medium or worse, Lookout calls it the package's install script and raises it to at least high. The window still shows the install.

  5. 05

    curl

    Outside the agent's window

    Uploads, a download piped into a shell, and raw tools like nc are flagged from the command. Open sockets are listed about once a second, with lsof on macOS and netstat -ano on Windows.

In the bundled demo, the read and the curl are one sh -c script, so they arrive as a single command line. The connection to port 4199 is recorded on its own.

What it catches

Rules, not a model, decide the level.

Each command and path is matched against a fixed list in the repo. The labels below are the ones the dashboard uses. A local model can summarize a session afterwards. It does not assign these levels.

  • Dangerous

    Decoy secrets

    On startup Lookout writes three fake files under ~/.seatbelt/bait: an AWS credentials file, a passwords file, and a fake SSH key. Each holds a random marker saved on first run. A read moves the file's access time. If that marker shows up later in a command, a file the agent writes, or a tool's output, that is critical too. The folder name still says seatbelt. The app rename has not landed there.

  • Dangerous

    Keychain and disk wipes

    security find-generic-password and the other Keychain dumps are critical. So is rm -rf aimed at your home folder, the disk root, or the Windows equivalents. Reading .ssh, .aws, .env, browser logins, or saved tokens is high, one step down.

  • Risky

    Sending data out

    curl and wget uploads, PowerShell Invoke-WebRequest with a body, scp and rsync to another machine, and raw connections. A POST that stays on localhost is treated as low, except the demo server on port 4199.

  • Risky

    Staying after a restart

    LaunchAgents, crontab, appending to .zshrc and the other shell startup files, scheduled tasks, registry Run keys, the Windows Startup folder, a new service, and turning Windows Defender off or adding an exclusion.

  • Worth a look

    Commands that are hard to undo

    sudo, a force-push, a screenshot, encoded PowerShell, and curl | sh are on the list. A package install by itself stays at Note. The install script it spawns is checked again.

  • Worth a look

    Servers it does not recognize

    Connections from the agent itself to Anthropic, OpenAI, GitHub, npm, PyPI, Apple, Google, and a few other hosts hardcoded in src/rules.js stay quiet. Anything else remote is medium, unless the process is a package manager or git talking to a CDN with no useful name.

The score

It starts at 850 and bottoms at 300.

Everyone starts at 850. Events cost points in six groups, each group has a cap, and a cost halves every 12 hours, so a quiet stretch brings the number back up. The floor is 300. Bands run from Excellent at 800, through Very good, Good, and Fair, down to Poor at 300.

  • 420

    Passwords and secrets

    A critical hit costs 260 before the fade, and before the cap.

  • 320

    Sending data out

    A high upload costs 140 before the fade.

  • 260

    Hidden background changes

    Startup files, launch items, scheduled tasks.

  • 200

    Risky commands

    Deletes, admin access, screenshots, encoded commands.

  • 90

    Unknown websites

    A medium hit on an unrecognized server costs 12 before the fade.

  • 30

    New software installed

    A package install at low risk costs 4. The cap on this group is small on purpose.

The full cost table, and the way a reason string is matched to a group, is in the white paper.

After it sees something

It can pause. On Claude Code it can refuse.

Auto-protect

The default is "Dangerous only", which means critical. Lookout freezes the agent and every process under it: SIGSTOP on macOS, NtSuspendProcess on Windows. You can let the session continue, or end it. It will not pause when it is only guessing which agent read a file. It also will not pause an action the Claude Code hook already blocked, because that action never started.

Pausing happens after the poll that saw the event. A command that finished inside the gap is already over.

Before the command, for Claude Code

pnpm protect on a folder adds a PreToolUse hook. Critical actions, and high ones that touch a secret, are denied. Other high and medium actions ask you, with the reason included. Lookout never answers "allow", so Claude Code's own prompts still apply to everything else.

If Lookout is not running, the hook blocks the action unless SEATBELT_FAIL_OPEN=1. The variable still has the old name. Codex and the other agents do not get this hook. They get the poll and auto-protect.

Privacy

The log stays on the computer.

The server binds to 127.0.0.1, port 4100 unless that port is taken or PORT is set. The dashboard is a local page. Events are appended to a jsonl file in the repo's data directory, or, for the desktop build, in the app data directory Tauri picks (the README names ~/Library/Application Support/dev.seatbelt.monitor).

A session summary calls Ollama at 127.0.0.1:11434 if it is running. Models with "cloud" in the name are skipped. If Ollama is down, you get a short note built from the events, with no model. When Lookout needs a hostname for an IP a watched process already contacted, it uses your machine's DNS resolver. There is no account and no telemetry call in the source.

FAQ

Short answers

Which agents does it know?

Process names: claude, codex, gemini, cursor-agent, copilot, opencode, amp, plus the scripted demo. Session logs are read only for Claude Code (~/.claude/projects) and Codex (~/.codex/sessions). The hook that can block before a tool runs is Claude Code only, and only in folders you protect with pnpm protect.

Does any of this leave my computer?

The event log is written to disk on that machine. Summaries go to a local Ollama, or they are written from the rules with no model. The one lookup Lookout makes on its own is reverse DNS of an address a watched process already connected to. That uses your resolver.

Can it stop a command, or only report it?

Both, with a gap. Auto-protect pauses the process tree after it sees a bad event. The Claude Code hook can deny or ask before the tool runs. A child process that is already running is only stopped if the pause lands in time. Lookout does not block packets.

Why is Windows "coming soon"?

The monitor has Windows code: a PowerShell process list, netstat, and NtSuspendProcess. That path has not been run on a real Windows machine, and there is no tested desktop build. The button stays disabled until a real installer exists. Linux is not supported.

What can it miss?

Anything that lives for less than about half a second can slip past the process poll. The first poll also ignores processes that were already running. Decoy access times can still show that a bait file was read, without saying which process did it. If two agents were active, Lookout reports the read and does not pause either of them. On macOS, pnpm deep asks Apple's eslogger for every launch and file open. It needs sudo and Full Disk Access, and it has not been tested end to end.

Does it need admin rights?

Normal mode does not. Deep mode on macOS runs sudo eslogger. The desktop app is signed ad hoc, not with an Apple Developer ID, so macOS warns the first time you open a downloaded copy.

Why do some files still say Seatbelt?

The product is being renamed to Lookout in the app. This site already uses the new name. Paths like ~/.seatbelt/bait, the hook script, and several environment variables still say Seatbelt, because that rename has not landed in the code this page describes.
